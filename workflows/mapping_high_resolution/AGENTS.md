# Mapping high-resolution workflow instructions

These instructions apply to all work under `workflows/mapping_high_resolution`.

## Session start

1. Read `knowledge_base/PROJECT_STATE.md` before opening large files.
2. Read only the section-specific evidence map needed for the task.
3. Do not read the complete manuscript, complete R analysis or original PDFs unless the requested task requires them.
4. Treat the repository as project memory. Do not rely on a previous chat as the only record of a scientific or processing decision.

## Source-of-truth map

- Raw measurements: `raw_data/`. Never edit these files.
- Prepared gas data: generated by `scripts/01_prepare_all_campaign_gas_data.R`.
- Regional weather: generated by `scripts/02_manuscript3_dwd_weather.R`.
- Manuscript 3 statistics, tables and figures: generated by `scripts/03_manuscript3_plots_tables.R`.
- Literature registry and verified notes: `knowledge_base/`.
- Active manuscript draft: `Manuscript_3_Mapping_high_resolution_concentration_Latex_draft/LaTex_drafts/20260813_Manuscript3_draft.tex`.
- Bibliography: `Manuscript_3_Mapping_high_resolution_concentration_Latex_draft/LaTex_drafts/references.bib`.

## Literature workflow

1. Search `knowledge_base/03_paper_evidence/` first.
2. Search `knowledge_base/02_source_cache/extracted_text/` second.
3. Treat the original PDF listed in `knowledge_base/00_source_registry/paper_registry.csv` as authoritative.
4. Inspect the PDF visually only for figures, complex tables, equations, scanned pages or ambiguous text extraction.
5. Never infer a paper's result from its title or abstract when the full text is available.
6. Distinguish the authors' findings, the authors' interpretation and the interpretation proposed for Manuscript 3.
7. Record every substantive numerical or methodological claim with a page, table or figure locator.
8. Never invent a citation, DOI, sample size, effect estimate, p-value or methodological detail.
9. Use `NOT REPORTED` when the source does not provide the requested information.
10. NotebookLM and Gemini may support discovery. Claims must be verified in the primary source before manuscript use.
11. Full extracted paper text is a local cache and must not be committed to Git.

## Manuscript workflow

- Use British English and a concise scientific tone suitable for *Biosystems Engineering*.
- Use author-year citations from `references.bib`. Do not type author-year citations manually.
- Preserve uncertainty and distinguish association from causation.
- Avoid rhetorical claims such as `proved`, `novel` or `optimal` unless explicitly supported.
- Prefer full stops to semicolons in manuscript prose.
- Preserve user edits and modify only the requested manuscript sections.
- Do not introduce new numerical results without tracing them to an R-generated table.
- Keep the complete drafting manuscript as one `.tex` file unless the user explicitly approves a split-file structure.

## Data and statistics

- Never manually calculate manuscript statistics.
- Generate reported values through the active R scripts.
- Do not silently filter zeros, negatives, outliers or low concentrations.
- Record every validity rule and filter in code and the manuscript.
- Preserve native cleaned data. Create derived analysis outputs in dedicated versioned output folders.
- Edit active scripts in place. Use Git history rather than copied script versions.

## File and version-control hygiene

- Do not place files directly in `D:\Data_Analysis_R`.
- Do not move or delete raw data, cleaned data, plots or manuscript files without explicit approval.
- Generated auxiliary LaTeX files and extracted source text are local artefacts.
- Do not commit or push unless the user explicitly requests it.
- Before committing, report the exact changed files and keep unrelated user changes untouched.
